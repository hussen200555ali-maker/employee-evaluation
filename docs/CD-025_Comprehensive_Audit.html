الملخص التنفيذي

تشريح هندسي شامل لست وحدات رئيسية في نظام تقييم الأداء. كل وحدة تُحلَّل عبر ثمانية أبعاد: نظرة عامة، مخطط البيانات، دورة الحياة، الشاشات والمسارات، نقاط التكامل، الأمان، الأداء، والفجوات.

الحكم: النظام وظيفي ومستخدم في الإنتاج، لكنه يحمل فجوات تتطلب تدخلاً قبل التوسع المؤسسي:

  1. 🔴 كلمات مرور بنص صريح في سجل التدقيق (UserController L388)
  2. 🔴 ApiController بدون مصادقة — أي شخص يعدّد الموظفين
  3. 🔴 مسارات تدميرية عبر GET (backup/restore/delete) — ثغرة CSRF
  4. 🔴 غياب جدول course_participants — لا ربط موظف↔دورة موثوق
  5. 🔴 خلط مقاييس في AveragesEngine — (0-100) مع (1-5) = خاطئ
  6. 🔴 صلاحيات مفقودة من البذور (evaluations.delete, training.evaluate, backup.manage)

الوحدة 1: الهيكل التنظيمي

1.1 نظرة عامة

الهدف: إدارة الفروع، الأقسام، الموظفين، المناصب.
الإنجاز: مكتمل وظيفياً (CRUD + فلترة + ترقيم صفحات + منع دورة المدير).
الالتزام المؤسسي: جزئي — لا سجل نقل، لا فحص اتساق فرع↔قسم.

1.2 مخطط البيانات

branches (id, name, location, manager_id→employees.id) │ 1:N departments (id, name, branch_id→branches.id) │ 1:N employees (id, emp_code[U], full_name, department_id, branch_id, manager_id(self-ref), position_id, is_active, join_date) │ N:1 positions (id, title, category ENUM(manager/deputy/staff/other))

الفهارس: employees على dept/branch/manager/position (L277-280). FKs: ON DELETE SET NULL.

1.3 دورة حياة البيانات

  • المدخلات: شاشات create/edit؛ API search؛ Excel.
  • المعالجة: فحص emp_code/full_name؛ لا فحص dept↔branch اتساق؛ دورة المدير فقط في update().
  • المخرجات: employees؛ snapshots في evaluations.
